# anvilkit-job-access-sidecar

Per-job access proxy for credential isolation, scoped model and artifact access, and protected control and result submission. It is the trusted access sidecar of DD-03 §5 in the AnvilKit architecture (`docs/architecture/execution.md` of `anvilkit-services`): the only process of a Job Pod that holds the Job's network identity and reaches Control. The launcher runs it as a Kubernetes native sidecar (an init container with `restartPolicy: Always`): it starts before the trusted harness and the kubelet stops it once the harness exited, so a finished launch never stays alive behind it.

## Boundary

- Runs as UID 10002 with no capability and the supplementary groups `[0, 10001]`. It creates its socket directory (`10002:0`, `0711`), `trusted.sock` (`10002:0`, `0660`) and `candidate.sock` (`10002:10001`, `0660`); the directory is a read-only mount in the other containers. Every step verifies the owner, group and mode it produced.
- Every accepted connection is bound to the peer's kernel-reported credentials (`SO_PEERCRED`): only UID 0 on the trusted socket, only UID 10001 on the candidate socket; anything else is closed at accept. Ancillary data (a delegated descriptor) closes the connection unserved. Each connection serves one request and closes.
- The execution scope is never claimed and never cached: it is what the trusted launcher registered with Control (`ExecutionService.GetInstance` by backend, launch key and the Pod UID the kubelet injected), read again from Control before every protected request — the scope, staging and serving inputs, transfers, results and relays. Historical physical ownership is not current permission: the answer authorizes only while the registration names the launch envelope's attempt, profile, launch key and epochs, the instance is the current one, the attempt is `LAUNCH_PREPARED` or `RUNNING` under the operation's current execution epoch, the operation is not fenced (no cancel or hold intent, not terminal, not reconciling) and the attempt and operation deadlines have not passed. A registered but non-current instance (a duplicate Pod) never gains authority; a closed attempt, a fenced operation, a moved epoch or a passed deadline ends it (`403 STALE_EXECUTION`, `NO_AUTHORITY`, `DEADLINE_EXCEEDED`); an unregistered Pod, an unreachable Control or a Control that reports no operation state authorizes nothing (`503`). Like Control's own acceptance, a pending cancel alone still lets the trusted observer's result of the running instance reach Control.

## Routes

| Socket | Route | Behaviour |
|---|---|---|
| candidate | `GET /v1/inputs/{name}` | Bytes of a permitted input the trusted harness staged, served only inside an execution authority Control confirms now; anything else `404` |
| candidate | `POST /v1/model/relay` | The controlled model relay (P11): the caller states the call id, route, messages, tools, output bound, exposure and an optional deadline; the sidecar refuses anything else (a binding, a key, a digest) with `400 INVALID_ARGUMENT`, confirms the scope, binds the request to the registered instance (tenant, operation, attempt, instance, execution epoch; the deadline capped by the attempt's), digests the scope with the caller's exact bytes, forwards it to the Model Proxy under the sidecar's own identity — the caller's headers go nowhere — and relays the Proxy's answer as it arrives (the error envelope or the frame stream); the same bytes reenter the same call. Without a configured Proxy (`ANVILKIT_SIDECAR_MODEL_PROXY_URL`) `503 DEPENDENCY_UNAVAILABLE`; never a direct provider or network fallback |
| candidate | everything else | `403 ROUTE_FORBIDDEN` |
| trusted | `GET /v1/scope` | The scope Control confirms now; `503 SCOPE_UNAVAILABLE` until registered, `503 DEPENDENCY_UNAVAILABLE` while Control cannot be asked, `403 NO_AUTHORITY` for a non-current instance, `403 STALE_EXECUTION` once the attempt or operation ended the scope, `403 DEADLINE_EXCEEDED` past the deadline |
| trusted | `PUT /v1/inputs/{name}` | Stages a permitted input under a confirmed scope, verified against the digest the launch envelope declares |
| trusted | `POST /v1/inputs/{name}/loads` | P13-04: loads an input the launch envelope binds to an artifact handle through Control's `ReadArtifact` (the scoped download capability is issued only under an authorized relationship of this instance's operation to the artifact — its brief, an accepted stage of one of its attempts — while the instance is the current one of an executing attempt), verifies the bytes against Control's record and the envelope digest and stages them; the capability never leaves the process and the candidate sees bytes only |
| trusted | `GET /v1/inputs/{name}` | The staged bytes back to the trusted harness (the same authority as the candidate route) |
| trusted | `GET /v1/stages/{attemptId}` | P13-04: the accepted stage of another attempt of this operation as Control records it (`GetAcceptedStage` with the operation relationship checked by Control); `404 NOT_FOUND` otherwise — the first question of a cross-attempt repair, never a resend |
| trusted | `POST /v1/transfers` | `BeginTransfer` under the scope, the one PUT the capability authorizes, `FinalizeTransfer` naming the object version and the current instance; the capability never leaves the process |
| trusted | `POST /v1/results` | `AcceptResult` under the current instance and execution epoch; a repeat of the same bytes reenters the same stage, another result is refused by Control |
| trusted | `GET /v1/results` | The accepted stage of the attempt as Control records it (`GetAcceptedStage`: identity, verdict, result digest, epochs, bound artifacts with their object versions; `404 NOT_FOUND` until a result is accepted), read under the result authority — the first question of the P12 joint stage recovery, never a resend or a reopening |
| trusted | `POST /v1/model/relay` | The same controlled model relay for the trusted harness's experts |
| trusted | `/v1/knowledge/…` | Trusted expert relay; `503 DEPENDENCY_UNAVAILABLE` until its unit wires an upstream |
| trusted | `POST /v1/mcp/calls` | MCP tool-call relay (P19): the caller sends only `commandId`, `grantId`, `grantRevision`, `method`, `arguments` (and an earlier `deadline`); the sidecar binds the confirmed scope (tenant, the operation's project and actor, operation, attempt, instance, epoch), namespaces the command by instance and digests the exact bytes, then calls MCP's `CallService.CreateCall` (`ANVILKIT_SIDECAR_MCP_ADDRESS`; plaintext DEVELOPMENT_ONLY or the workload certificate under mtls). Repeating the identical request answers the original call and never sends again; `503 DEPENDENCY_UNAVAILABLE` without an MCP placement |

## Configuration

One reviewed, secret-free `config.yaml` (baked into the image) plus the allowlisted environment: `ANVILKIT_SIDECAR_CONTROL_ADDRESS`, `ANVILKIT_SIDECAR_IDENTITY_MODE` (`mtls`, the default of every environment since P0.1: the workload certificate the Job template mounts read-only into this container alone at `/etc/anvilkit/identity`, `identity.mtls` in the file, watched and reloaded as a whole, Control and MCP verified by their DNS SANs `identity.mtls.server_name` / `mcp.server_name`; `development` is the plaintext identity, admitted only by an image whose file sets the top-level `development.enabled: true`, which the shipped file does not; the default `disabled` makes the process exit before a socket exists), `ANVILKIT_SIDECAR_BACKEND`, `ANVILKIT_SIDECAR_LAUNCH_KEY`, `ANVILKIT_SIDECAR_POD_UID` (downward API `metadata.uid`), `ANVILKIT_SIDECAR_LAUNCH_ENVELOPE`, and the Model Proxy placement `ANVILKIT_SIDECAR_MODEL_PROXY_URL` with, under the development identity, the DEVELOPMENT_ONLY bearer token `ANVILKIT_SIDECAR_MODEL_PROXY_TOKEN` (under `mtls` the same workload certificate files identify the sidecar to the Proxy); `model_proxy.timeout` bounds one relayed call. The launch facts, the Proxy placement and the token are refused inside the file.

## Verification

`go build ./... && go vet ./... && go test ./...` (the process tests spawn the sidecar as UID 10002 and a candidate as UID 10001 and need a root caller; they skip otherwise; they cover a closed attempt, a cancel fence, a fenced or terminal operation, epochs that differ from the envelope, an unregistered Pod, an unreachable Control, a Control without operation state, and the model relay against a Proxy double: the confirmed scope as the binding, the sidecar's own identity, the caller's binding refused on both sockets, a closed attempt ending the relay). The parent's `tests/integration` relays through a real sidecar to a real Proxy and Control. The module requires the contracts module as an explicit versioned dependency: the version is the generated line below (a published tag, served by `proxy.golang.org` and checksum-database verified), so `GOWORK=off go build ./... && go vet ./... && go test ./...` and `docker build .` work from this repository alone; inside the `anvilkit-services` workspace it builds against the contracts checkout.
